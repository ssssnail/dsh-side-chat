# 临时会话（side chat）

DSH Web 的插件：在主会话旁边开一个**只读的临时会话**。围绕主会话**已完成**的内容提问，模型只能读工作区，讨论历史不落盘、不改文件、关闭即清空。

## 它做什么

- 侧栏输入框左侧的按钮打开一个右侧标签「临时会话」。
- 打开时做主会话的**快照**：取最后一次 `turn/end` 作为边界，边界之后的未完成轮次全部排除（不让对方看到半截工作）。
- 讨论保留一个**内存 Session**记录事件和用量；模型请求统一使用打开时派生的消息快照、讨论摘要及近期回合。Session 的 seed 从原日志序号 0 开始，预算裁剪和压缩作用于实际请求，不改动主会话。未改变的消息前缀可供模型服务复用缓存，具体命中仍取决于模型和请求配置。
- 只读工具 `read` / `glob` / `grep`，工作区受限（realpath 校验 + 沙箱），出界与未开放的工具会被拒绝，并把替代方法作为工具结果交给模型；连续拒绝或重复失败后，只允许一次无工具收尾。正常查询不限制轮数；单次回答超过 10 分钟会中止，保留部分内容并允许继续提问。
- 回答逐字流式；每轮带用量胶囊（缓存命中率、输入/输出、首字与总耗时，可点开明细）。默认继承主会话模型，可把回答放进主会话草稿、随时停止。
- 标签关闭前显示二次确认；取消保留讨论，确认后中断请求并清空。关闭期间迟到的创建响应和旧流不能恢复面板或写入新实例。隐藏面板不等于关闭，标签生命周期结束或插件停用时也会清理。

当前 UI 尚未接入 `/` 命令、模型切换菜单和压缩按钮；`/side-chat/model` 与 `/side-chat/compact` 是宿主 API，不是输入框中的 slash 命令。

## 架构

| 半边 | 文件 | 职责 |
|---|---|---|
| 宿主 | `index.js` | 路由 `/side-chat/*`：`open` `send` `cancel` `close` `model` `models` `compact` `ping`；空闲实例回收 |
| 宿主 | `host/snapshot.js` | 主会话快照：边界、投影、预算裁剪、模型路由继承 |
| 宿主 | `host/runtime.js` | 讨论运行时：内存 Session、真实事件、逐字流、回合与拒绝策略 |
| 宿主 | `host/readonly-tools.js` | 只读工具箱：白名单、realpath 边界、拒绝分类 |
| 宿主 | `host/prompt.js` | 讨论指令与边界标记 |
| 客户端 | `client.js` | 入口按钮、面板、主会话 Markdown 渲染器、折叠过程、用量、回答操作、失败恢复及关闭确认 |

样式变量与尺寸逐条抄自宿主模块 `InputBar` / `MessageItem` / `StatsPills` / `ReasoningRow` 的 `.module.css`。

### 为什么客户端自己渲染转录

主会话的 composer 通过 Session Controller 启动或恢复普通 Agent；当前公开创建路径会接入持久化，没有每个会话独立的临时选项。完整 Conversation 组件也依赖这条激活路径。因此本插件使用自己的请求生命周期和面板，复用公开的 `MarkdownText` 与主会话样式，保持只读和关闭清空，不修改 dsh。

讨论的事件记录只调用 `SessionStore.prepare()`，由插件私有内存持有，不进入公共 SessionStore。它可以本地追加并投影真实 Session 事件，但不会发布 `session/created`、`session/event` 或全局 Agent 流事件。这样既不进入主侧边栏目录，也不触发普通会话的监听器。

## 保证（结构性，不靠提示词）

- **不落盘**：会话仅通过 `ctx.sessions.prepare()` 建立私有内存记录，不调用 `enter/announce` 或 `agentLoop`，不挂载日志写入器；真实 SessionStore 测试确认它不进入公共目录。
- **不写工作区**：只暴露三个只读工具，且路径经 realpath 校验限制在绑定工作区。
- **不干扰主任务**：`ctx.llm.stream` 不带 `sessionId`，也不发布 Agent 生命周期事件；发送、停止、模型路由与主会话独立。
- **边界干净**：快照在最后一个 `turn/end` 处切开，未完成轮次与半截工具调用不进入讨论；尚无完整回合时继承内容为空。
- **搜索可中断**：`grep` 正则、`glob` 通配符和 `grep.include` 过滤在独立 Worker 中匹配，单批匹配最多 1 秒，支持取消；不会把正则回溯放到 Host 主线程。
- **指令可达**：完整讨论规则以 `system` 消息放在快照之后；普通聊天、收尾和压缩都使用真实 dsh 请求投影支持的消息形式。压缩摘要以只供参考的用户上下文保留，避免被工具目录投影过滤。
- **压缩一致**：压缩与发送互斥，关闭会取消正在压缩的请求；摘要替代较早讨论并进入下一次模型请求。

## 安装

这是可直接安装的 DSH Web bundle：包含 Host、Client 和配置 patch，无需单独构建。当前已用 DSH `0.2.0-rc.2` 的真实安装器在独立临时 profile 中验证打包安装、bundle 启用、入口解析与包内搜索 Worker。该检查不等于真实模型或完整浏览器验收。

从本地目录安装：

```bash
dsh plugin --profile web add link:/Users/snail/projects/side-chat --registry=https://registry.npmjs.org/
```

也可在 DSH 会话中调用安装工具：

```bash
# 在本机 DSH 会话里（注意 registry：该 profile 里 agent-live 的 pin 在 npmmirror 上不存在）
plugin_manager install_bundle  target=link:/Users/snail/projects/side-chat  registry=https://registry.npmjs.org/
```

`private: true` 只阻止误发布到 npm；不妨碍本地目录、Git 仓库或 `.tgz` 安装。目前没有发布到 npm，不能通过包名从 npm 下载。

装好后**刷新页面**。宿主侧改动需要重启 `dsh web`（Node 缓存 ESM：模块世代是进程启动时加载的，`/side-chat/ping` 的 `revision` 字段用来自查）。

```bash
npm test                 # 宿主、客户端及生命周期/搜索回归检查（全离线）
npm run test:real        # 真实文件系统 + 已安装 dsh 的真实 SessionStore；不调用模型
```

`test:live` 需要运行中的 profile 与 `DSH_SESSION_ID`，会花一次真实调用，因此不进 `npm test`。

本次验证：53 项离线检查和 27 项真实文件系统／SessionStore 检查通过。独立浏览器预览使用实际主会话 Markdown 组件与模拟模型流，检查了输入焦点和 36–180px 伸缩、生成时阅读历史、回到最新、过程折叠、复制及草稿追加、失败恢复、刷新后重开、浅深色和 400px 窄屏，正常流程控制台无报错。关闭确认及跨实例隔离由回归测试覆盖。另在真实 DSH 页面验证：取消保留讨论，确认后临时标签与面板均移除（数量均为 0），Chat、Trajectory 与 Agent Live 标签仍在；测试未发送模型请求。关闭前拦截会由宿主记录预期的确认提示错误，确认后的移除未产生额外错误。本次未重启用户现有 dsh，也未重新调用真实模型；上述模拟流与回答体验仍需在真实模型下体验；关闭修复仅需刷新页面。


## 运维

- **令牌**：无。路由是回环地址上的普通 HTTP 路由，没有鉴权（这是刻意的：它只服务本机的 GUI）。
- **空闲回收**：实例空闲 30 分钟后自动销毁；插件停用时全部销毁。
- **落盘检查**：`ls ~/.dsh/sessions/*/ | grep discussion` 应为空。

## 工具边界与拒绝策略（当前行为）

讨论会话的模型只被声明三个只读工具 `read` / `glob` / `grep`，由本插件自己实现（`ctx.fs` + realpath 边界），工作区限定为会话绑定的那块。

| 情况 | 行为 |
|---|---|
| 调了未声明的工具（bash / write / edit …） | 拒绝，并告知"本次只读会话只有 read/glob/grep"，**给一次机会**改用只读工具；连续两轮全被拒后，停止工具并生成一次最终答复 |
| 路径在工作区之外 | 同样给一次机会，并回报可访问范围 |
| **重复一个已经失败的调用** | 不再执行相同调用，转为一次无工具收尾；重复检测只作用于当前轮 |

完整讨论指令说明历史工具调用不代表当前权限，并提供 glob / grep / read 的用途。拒绝反馈直接进入模型上下文；收尾请求省略工具声明，程序也不再执行任何工具。如果收尾仍产生工具调用或空答复，则显示核查未完成，不能标为成功。

### 为什么是白名单而不是黑名单

`ctx.tools` 的契约允许无 Agent 调用（`ToolExecutionInput.agent` 是可选的，`schemas()`/`get()` 省略 scope 即全局视图），所以**技术上**可以列出全局工具、把"写/改/执行"类按名字挡掉、其余交给 `ctx.tools.execute`。但那会把保证方式从"结构上不可能改"换成"我按名字维护了一份清单"：

- `restrict()` / `guard()` 的语义是 **agent 作用域**的（`guard` 文档：普通上下文注册的**全局生效**）；没有 agent 就没有正确的作用域去收窄工具，也无法安全地遮蔽写工具；
- 工作区绑定、沙箱策略、审批管线同样是 agent 作用域，无 agent 调用会落到全局/默认上下文；
- 任何**新出现**的工具（插件、MCP、`run_code`、终端控制）默认就在清单之外。

因此维持"默认拒绝"。要真正放开采到的能力（`web_fetch` 等）按逐个加入白名单来做；要"全部可用"则必须让讨论会话拥有一个真 Agent（`agentCtx.tools.restrict({allow:[…]})` 给的是真工具 + 真策略）。

## 面板与主会话的对齐

- 流式答复只在用户停留底部时自动跟随；向上滚动可阅读历史，通过「回到最新」按钮、滚回底部或发送新问题恢复跟随。
- 工具详情默认折叠，失败状态仍可见；过程提示在继续输出或本轮结束后清除。
- 打开面板不调用模型，也没有人为等待；超过 200ms 才显示加载动画。宿主 `open` 调试日志记录快照、工具准备、内存会话及总耗时。
- 讨论 prompt 按问题需要简洁直答，不固定段数、不默认使用编号清单，也不强行压成一句话，关键缺失证据在对应结论旁说明，不要求固定的声明段落；工具轮次中的正文原样保留在默认折叠的「查阅过程」中，最终回答单独展示；不裁剪模型正文。

- 模型正文直接使用主会话公开的 `MarkdownText` 组件，保留流式解析、列表、表格、代码块与公式渲染；复制和放入草稿仍使用原始 Markdown 文本。

- 打开新讨论自动聚焦输入框，多行输入自动增高到最多 180px，清空后缩回 36px。刷新或讨论结束后的空面板可重新打开，打开失败可重试，回答失败可将原问题放回输入框编辑；新实例不保留旧历史或草稿。
- 最终回答下方是两个低调的 28px 图标按钮：复制、导入到主会话。悬停显示用途，完成后短暂变为勾号并更新提示，保留键盘焦点及屏幕阅读器反馈；失败时显示提示。只操作点击的最终回答；导入追加到现有主会话草稿，不自动发送。
- 输入区按内容计算高度，文本区最小 36px；左右内边距 16px，统计行上方 4px、底部 4px。卡片使用主会话相同的背景、描边和阴影变量；发送按钮显式设置 `corner-shape: round`，避免全局主题将圆形变为圆角方形。
- 输入框下方是统计行（`.sc-statsline`，固定 22px，与主会话那行 pills 等高：`line-height 20px + 上下 1px`），**无数据时也渲染**，显示 `0 轮 0 步 · 0 tok · 0 tok/s · 缓存命中 0%`。
- 模型名右侧显示继承来的推理强度（`route.reasoningEffort`）。

## 两条踩坑记录（改客户端必读）

1. **改 `client.js` 之后必须重新发布**（Plugin Manager 里 disable→enable）再刷新。客户端模块 URL 带内容修订号，改文件不发布会让浏览器 404，表现为"入口/面板突然消失、控制台没有插件报错"。
2. **不要在入口注册上做"简化"**。`ctx.slots.register` 的选项保持 `{ name, id, order, locale }`；删除组件定义而留下引用时，inject 回调抛的 `ReferenceError` 会被槽位机制**吞掉**——面板照常注册、入口静默消失、没有任何报错。客户端测试现在会扫描文件，发现 `h()` 引用未定义组件或丢失样式表就失败。
